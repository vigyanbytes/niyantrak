# Niyantrak and ISO/IEC 27001 (information security)

> **Mapping only. No certification claim.** Niyantrak is not certified against ISO/IEC 27001 and does not certify your
> organisation. This page shows which Annex A controls Niyantrak's features can provide evidence for when AI agents
> and AI models are part of your scope. Not audit advice.

## The standard in one paragraph

ISO/IEC 27001:2022 sets requirements for an **information security management system (ISMS)**. Annex A lists 93
reference controls in four themes: organisational (5.x), people (6.x), physical (7.x) and technological (8.x). You
choose and justify controls in a Statement of Applicability. AI agents that run commands and AI models that receive
customer data bring new risks into the same controls.

**Source:** ISO/IEC 27001:2022, <https://www.iso.org/standard/27001>. The standard is a paid document. Control
numbers and titles below come from public summaries and are **unverified against the purchased text**.

## Annex A controls relevant to AI agents and models

Status: **Helps** (free edition, code here) · **Partial** · **Commercial** · **Yours**.

### Logging and monitoring

| Control | Title | Niyantrak | Status |
|---|---|---|---|
| 8.15 | Logging | Gate logs every agent tool-call decision, allow included: rule id, mode, agent, OS user, host role, project (`which`), command sha256 (`niyantrak/gate/events.py`). 6W events for governed activity (`niyantrak/telemetry/`). Bootstrap installs auditd rules for identity, sudo, SSH, units, firewall, secrets and gate files (`bootstrap/niyantrak-bootstrap.sh`). | Helps |
| 8.16 | Monitoring activities | Activity (6W) screen, `niyantrak telemetry ask` (read-only SQL). No alerting. | Partial |
| 8.17 | Clock synchronisation | Events stored in UTC. NTP setup is yours. | Yours |
| 5.28 | Collection of evidence | Tamper-evident 6W store (hash-chained manifest, `telemetry verify`); decision log with per-segment sha256 (`decisions verify`). Signed evidence packs: Commercial. | Partial |
| 5.33 | Protection of records | Append-only stores; tamper detection, not tamper prevention. | Partial |

### Access control and privileged actions

| Control | Title | Niyantrak | Status |
|---|---|---|---|
| 5.15 | Access control | Panel binds 127.0.0.1 by default; join approvals accepted only from loopback (`niyantrak/panel.py`). | Partial |
| 5.16 | Identity management | People from the OS login via NSS (local, SSSD/AD, authd, Kanidm) with a stable directory id (`niyantrak/identity.py`); machines by SSH host-key-signed cards (`niyantrak/card.py`). | Helps |
| 8.2 | Privileged access rights | Gate denies service, firewall, deploy and power changes (`prod.*`) and destructive commands by AI agents. It blocks listed actions; it does not lower the agent's privileges. | Partial |
| 8.5 | Secure authentication | Join: single-use 256-bit token (only its hash stored), TLS pinned by fingerprint, changed host key refused (`niyantrak/join.py`, `tls.py`). Bootstrap turns off SSH password logins. The 6W sink and panel API have no authentication of their own. | Partial |
| 8.18 | Use of privileged utility programs | Gate hard stops on disk formatting, raw block writes, `zfs destroy`, recursive deletes of system paths. | Partial |
| 8.9 | Configuration management | As-built docs from signed node cards. Desired-state reconciler with approvals: Commercial (in build). | Partial |
| 8.32 | Change management | Gate denies deploys and production changes by agents; decisions record changes and who made them. | Partial |

### Data leakage, masking and personal data

| Control | Title | Niyantrak | Status |
|---|---|---|---|
| 8.11 | Data masking | `niyantrak scan` replaces identifiers with placeholders. Masking live model traffic and putting values back: Commercial (in pilots). | Partial / Commercial |
| 8.12 | Data leakage prevention | Detection of identifiers before a model call (free); gate denies agents reading credential files (`secret.path`); `tools/leak-scan.py` checks code history for keys. Blocking leaks on live model traffic: Commercial. | Partial |
| 5.34 | Privacy and protection of PII | The free tools never store message text or identifier values. | Partial |
| 8.10 | Information deletion | No retention schedule in the free edition. Reclaim map expiry and erasure: Commercial. | Partial / Commercial |

### Suppliers and cloud (model providers are suppliers)

| Control | Title | Niyantrak | Status |
|---|---|---|---|
| 5.19–5.22 | Supplier relationships, agreements, ICT supply chain, monitoring | `where` / `route` fields show which model provider each request went to — evidence for supplier monitoring. Core package has no runtime dependencies (`pyproject.toml`). No SBOM or signed releases yet. | Partial |
| 5.23 | Information security for use of cloud services | Shows what a cloud model would receive. Local-only routing of sensitive data: Commercial. | Partial |

### Incidents

| Control | Title | Niyantrak | Status |
|---|---|---|---|
| 5.24–5.27 | Incident planning, assessment, response, learning | Records to reconstruct agent actions and data flows. No incident workflow. | Partial |

## Limits

No ISMS documents (policies, risk register, Statement of Applicability), no vulnerability scanning, no backup, no
endpoint protection. Niyantrak adds AI-specific controls and evidence to an ISMS you already run.
