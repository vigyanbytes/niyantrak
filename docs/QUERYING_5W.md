# Querying 5W activity and decisions

Every 5W event says **who** acted, **whom** it was for, **what** happened, **where** the data went and **why** it was
allowed or stopped (see [5W.md](5W.md)). This page shows how to ask that record questions — in plain words or in
SQL — and get the answer as a table, CSV, JSON, Markdown or Parquet.

All output below is real: it was produced by running the commands shown against the sample team from
`tools/demo-data.py` (seed 7, 14 days ending 2026-10-23). The team, machines and paths are fictional.

> **Sample data.** asha, ravi, meera and tomas use Claude Code, Codex and Antigravity on control-01, build-01,
> gpu-01 and three laptops; a support bot sends customer and patient questions through the gateway. In real use
> `who` comes from the operating system login (local account, SSSD/AD, authd/Entra ID or Kanidm), never typed in.

## Set up the sample data

Needs the `telemetry` extra (pyarrow + DuckDB).

```console
$ pip install ".[telemetry]"
$ python3 tools/demo-data.py --out demo --end 2026-10-23
Sample data — fictional team generated by tools/demo-data.py
798 5W events and 22 decision-log items, 14 days ending 2026-10-23 -> demo
$ export NIYANTRAK_TELEMETRY=$PWD/demo/telemetry NIYANTRAK_DECISIONS=$PWD/demo/decisions
$ niyantrak telemetry verify            # the hash-chained manifest and every segment check out
```

Without `NIYANTRAK_TELEMETRY` / `NIYANTRAK_DECISIONS` the commands read the panel's own stores
(`<state root>/telemetry` and `<state root>/decisions`); `--dir` and `--decisions` choose other folders.

## Two commands

| Command | What it does |
|---|---|
| `niyantrak telemetry ask "<question>"` | matches the question to one of ten built-in templates by keywords, prints the exact SQL, runs it, prints the answer. **No AI model is involved** — the same question always gives the same SQL. `--as-of YYYY-MM-DD` sets the last day of the window (default today, UTC); `--days N` its length (default 7, "this week"); `--list` prints every template with its SQL |
| `niyantrak telemetry sql "<SELECT …>"` | runs one SQL query of your own |

Both take `--format table|csv|json|md|parquet` and `--out FILE` (required for Parquet).

### Tables

| Table | One row per | Columns |
|---|---|---|
| `ev` | 5W event | `event_id, ts, who, who_id, whom, what, where, why, agent, route, machine, session, rule_ids (list), outcome, entity_counts (map type → count), entity_total, source, schema` |
| `decisions` | decision, work item or thing in the decision log | `id, kind, status, ts, title, user, agent, product` — `status` is derived from the append-only log (see [ARCHITECTURE.md](ARCHITECTURE.md)) |

`where` is a SQL keyword: quote it as `"where"`.

### Read-only by construction

The rows are copied into an in-memory DuckDB database; then file and network access is switched off and the
configuration is locked. A query cannot change the stores, read other files, write files or switch access back on.
Only a single `SELECT` (or `WITH … SELECT`) is accepted, and at most 10,000 rows are returned.

```console
$ niyantrak telemetry sql "DELETE FROM ev"
telemetry sql: read-only: only SELECT (or WITH … SELECT) queries are allowed
$ niyantrak telemetry sql "SELECT * FROM read_csv('/etc/passwd')"
telemetry sql: Permission Error: Cannot access file "/etc/passwd" - file system operations are disabled by configuration
```

## Ten questions → SQL → answers

The window is the seven days 2026-10-17 to 2026-10-23. Gate rule ids (`git.force_push`, `secret.path`,
`prod.deploy`, …) are the agent gate's hard stops (`niyantrak/gate/engine.py`); `RB-ROUTE-…` ids are routing rules.

### 1. Who ran destructive commands this week?

```console
$ niyantrak telemetry ask "Who ran destructive commands this week?" --as-of 2026-10-23
```

SQL (`destructive-this-week`):

```sql
SELECT who, agent, machine, count(*) AS attempts,
       count(*) FILTER (WHERE outcome = 'blocked') AS blocked,
       string_agg(DISTINCT r, ', ' ORDER BY r) AS rules
FROM ev, unnest(rule_ids) AS t(r)
WHERE regexp_matches(r, '^(fs|disk|docker|git)\.') AND ts >= DATE '2026-10-17' AND ts < DATE '2026-10-24'
GROUP BY ALL ORDER BY attempts DESC, who, agent, machine
```

Answer:

```text

-----  -----------  ------------  --------  -------  -----------------------------------------------

(4 rows)
```

### 3. What was blocked on each machine?

```console
$ niyantrak telemetry ask "What was blocked on each machine?" --as-of 2026-10-23
```

SQL (`blocked-per-machine`):

```sql
SELECT machine, count(*) AS blocked,
       count(DISTINCT who) AS people, count(DISTINCT agent) AS agents,
       arg_max(r, n) AS top_rule
FROM (SELECT machine, who, agent, r, count(*) OVER (PARTITION BY machine, r) AS n
      FROM ev, unnest(rule_ids) AS t(r)
      WHERE outcome = 'blocked' AND ts >= DATE '2026-10-17' AND ts < DATE '2026-10-24')
GROUP BY machine ORDER BY blocked DESC, machine
```

Answer:

```text
machine       blocked  people  agents  top_rule
------------  -------  ------  ------  ---------------
build-01      8        3       2       fs.rm_protected
laptop-ravi   3        1       2       secret.path
laptop-asha   2        1       1       secret.path
laptop-meera  2        1       2       secret.path
(4 rows)
```


SQL (`top-whom`):

```sql
SELECT whom, count(*) AS events, sum(entity_total) AS identifiers_found,

FROM ev
WHERE whom IS NOT NULL AND ts >= DATE '2026-10-17' AND ts < DATE '2026-10-24'
GROUP BY whom ORDER BY events DESC, whom LIMIT 10
```

More ideas:

```sql
-- every rule that fired, with how often
SELECT r AS rule, count(*) AS n FROM ev, unnest(rule_ids) AS t(r) GROUP BY r ORDER BY n DESC;
-- one person's week, by directory id rather than display name
SELECT CAST(ts AS DATE) AS day, outcome, count(*) FROM ev WHERE who_id = 'kanidm:uid:70002' GROUP BY ALL ORDER BY 1;
-- decisions in force, newest first
SELECT id, title, ts FROM decisions WHERE kind = 'DECISION' AND status = 'in force' ORDER BY ts DESC;
```

clean data you can pipe.

## Questions `ask` does not understand

`ask` never guesses. If no template matches, it lists the questions it knows and exits with status 2; write the SQL
yourself with `niyantrak telemetry sql`, or print every template with `niyantrak telemetry ask --list`.

```console
$ niyantrak telemetry ask "what is the weather"
Questions ask understands:
  Who ran destructive commands this week?
  Which agent touched credential files?
…
```

## Elsewhere

- The panel's **Activity (5W)** screen draws the same store (`niyantrak telemetry activity --days 7` prints its data).
- `niyantrak decisions ask "…"` answers questions about the decision log with a **local** model only; the exact
  matching rows are always printed first.
- The materialized view is a plain Parquet file (`<store>/view/events.parquet`) — any Parquet reader can open it.
